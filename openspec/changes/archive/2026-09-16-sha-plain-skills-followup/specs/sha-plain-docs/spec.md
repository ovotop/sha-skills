# Spec: sha-plain-docs

## Purpose

受控文档写作技能。当用户要求撰写或改写技术文档（操作手册、API 说明、更新日志、故障排查等）时，该技能按目标语言应用金字塔原理的结构化组织与中文受控写作（或精简 STE）规则，产出可被确定性 lint 验证的清晰、无歧义文档。

## MODIFIED Requirements

### Requirement: 金字塔结构

文档 SHALL 按金字塔原理组织：结论或要点先行（每个段落首句为主题句）；信息按归类分组展开（同一层级的条目遵循统一逻辑分类，组内互斥组间穷尽）；以上统下（子层级从属于父层级，不出现信息密度倒挂）；操作步骤按实际执行顺序排列。

文档 SHALL 遵守以下结构护栏：①序言只提示读者已知的背景与冲突（S+C），不得引入新信息（序言 ≠ 摘要）；②章节标题 MUST 是判断句或完整结论，不得用"背景/介绍/概述"等名词标签；③关键句层次默认归纳（"建议 X，因为 1/2/3"），同组内不得混用演绎与归纳；④每层首句 MUST 是判断句，禁止"存在以下 N 个问题：""本次更新的变更与使用限制如下"这类空壳引导句，也禁止在标题已给出判断后用空壳条目复述标题。

#### Scenario: 结论先行

- **WHEN** 文档包含概述或结论性内容
- **THEN** 结论出现在该章节开头而非末尾

#### Scenario: 步骤顺序

- **WHEN** 文档包含操作步骤
- **THEN** 步骤按实际执行顺序编号排列，前置条件与风险警告位于相关步骤之前

#### Scenario: 章节标题为判断句

- **WHEN** 文档包含章节标题（如"背景"）
- **THEN** 标题改写为包含结论的判断句而非名词标签

#### Scenario: 标题已给判断时正文不复述标题

- **WHEN** 章节标题是判断句（如"重试在 3 次失败后停止"，或标题如"本次更新优化了性能并修复了若干问题"）
- **THEN** 正文不再复述该标题判断，而是直接写依据、条件、操作或后果

#### Scenario: 序言不引入新信息

- **WHEN** 文档含序言且其中出现正文才有的新信息
- **THEN** 该新信息移出序言，序言仅保留读者已知的背景与冲突

### Requirement: 确定性验证

技能 MUST 提供可执行的 lint 脚本（check_plain.py），支持三类检查：

1. **基础单文件检查**（默认，无需原稿）：句长双层（无逗号单句 ≤40 字，逗号分隔构件 ≤20 字）、禁用黑话命中、标点与空格规范；超 30 字且语义明确的句子 SHALL 标注为"需确认语义明确"而非硬性失败。违规 MUST 以清单形式输出。
2. **强断言来源标记检查（check_facts）**：扫描**事实型强确定性词**（一定/绝对/必定/必然/肯定/显然/无疑/确实/确定/从不/总是/永远；en：always/never/definitely/certainly/obviously/proven），检查其所在句或紧邻前句是否含可核对的来源成分（根据/依据/据/来自/显示/表明/报告/文档/监控/日志 + 具体来源实体，或（）内的来源标注）。**有可核对来源上下文的断言（改写/重讲/引用文档场景）无来源标记即违规**；绿场写作（无原稿、依托模型知识）场景该检查 SHALL 降级为告警而非硬性违规，交由语义层（人/LLM-judge）判定。"确认"一词不得单独作为来源标记（需与明确来源主语连用）。**规范型情态（必须/不得/禁止；en：must）不属事实断言，SHALL 单独列为 `normative_modality` 类别并默认为告警（warning），不需要来源标记**。
3. **删改对比检查**（`--source` 模式，改写场景）：对比原稿与输出，检测显式警告标记词（仅/不得/除非等）在原稿->输出的缺失。该模式仅在提供原稿时执行；未提供原稿时脚本 MUST 明确提示"删改对比需 --source"，不得伪称已检测。

#### Scenario: 脚本校验

- **WHEN** 文档写作完成且用户要求验证
- **THEN** 运行 lint 脚本并输出违规清单（句长、黑话、来源标记、标点分类）

#### Scenario: 分级判定

- **WHEN** 短句为 30-39 字且语义明确
- **THEN** 脚本标注为可接受，不列为违规

#### Scenario: 改写场景无来源强断言被检出

- **WHEN** 改写文档含"系统一定失败"且所在句及紧邻前句均无来源成分
- **THEN** 脚本将该断言列为硬性违规（结构层），提示补来源或降级语态

#### Scenario: 绿场写作强断言降级为告警

- **WHEN** 用户撰写全新文档（无原稿）且文档含强断言但无来源标注
- **THEN** 脚本以告警形式列出该断言供人工/LLM 复核，不计数为硬性违规

#### Scenario: 规范型情态不被当作无来源断言

- **WHEN** 文档含"用户必须配置超时时间"或"不得短于 60 秒"这类规范要求且无来源标注
- **THEN** 脚本将规范型情态列为 `normative_modality` 告警而非违规，不要求来源标记；改写场景是否新增了原稿没有的要求由语义层判定

#### Scenario: 未提供原稿时删改对比不可用

- **WHEN** 用户调用脚本检查新写文档且未提供原稿
- **THEN** 脚本跳过删改对比并提示该检查需 --source，而不是输出虚假的"对比通过"

#### Scenario: 提供原稿时检测删改

- **WHEN** 用户将改写后的文档与改写前原稿一并提交（--source）
- **THEN** 脚本对比两者，报告警告标记词（仅/不得/除非）被删除的具体位置
