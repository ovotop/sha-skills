# LLM-judge rubric — sha-plain-docs

用于评估 `outputs/output.md`。机械项（句长双层、禁词/黑话、强断言来源标记、标点、删改对比）**必须先由 `scripts/check_plain.py` 断言**；本 rubric 只负责脚本判不了的语义与结构项。
**每条独立判 PASS / FAIL 并附证据引用**（原文片段；无证据的 PASS 无效）。
来源支撑质量给 1–5 锚定分：5=来源真实且直接支撑；3=来源真实但仅相关；1=来源不存在或与结论相悖。

## 核心三问（置信阶梯，Oracle S6）

1. **被引用的来源在给定上下文中真实存在吗？**（原稿、用户提供的数据、或模型稳定知识）
2. **该来源是否真正支撑该结论？**（不是仅同时出现）
3. **无依据处是否出现事实型强语态？**（一定/绝对/必定/必然/肯定/显然/无疑/确实/确定/从不/总是/永远；`必须/不得/禁止` 是规范要求而非事实断言，不需要来源标记，但改写场景不得新增原稿没有的要求）

## 工作流合规

4. **判了文档类型并选了强度**（操作手册/安全警告/故障排查=完整；API 说明/更新日志=选择性；文案/叙事=不适用），拿不准时**问了用户**而不是静默套用。
5. **写中文文档前读了 `references/rules-zh.md`**（transcript 中可见）。
6. **跑了 `check_plain.py`**：transcript 中可见命令与退出码，且最终文档 `violations = 0`；改写场景用了 `--source`，绿场场景用了 `--greenfield` 并逐条复核告警。
7. **明确了绿场/改写场景**：绿场（无原稿）不得把告警当通过；改写（有原稿）强断言无来源必须补来源/降级/删除。

## 结构护栏（4 条）

8. **序言只提示已知**：序言不含正文才有的新信息（序言 ≠ 摘要）。
9. **标题是判断句/结论**，不是"背景/介绍/概述"式名词标签；标题已给判断时正文不复述标题。
10. **归纳优先不混用**：同一组内不混用演绎与归纳。
11. **无空壳句**：不出现"存在以下 N 个问题：""如下/以下"式空壳引导句后接无判断的条目；条目不复述标题/首句已给出的判断。
12. **步骤文档**：前置条件与风险在步骤之前；一步一动作、写清动作对象；每步有预期结果；末尾有失败停止条件与恢复。

## 事实与措辞

13. **未新增事实**：没有原稿/来源没有的数字、日期、条件或结论。
14. **系统自动行为与人工操作使用不同主语**，读者无需推断执行者。
15. **无黑话与机械直译**；**指代可定位**（无"该/其/此/上述/相关"作指代；`应该/其他/因此` 等固定词不算）。
16. **术语一致**：关键对象/动作/状态用首选术语，不为避免重复而轮换同义词。

## 判定汇总

- 任一核心三问 FAIL，或第 6 项（未跑脚本 / 有 violation）FAIL → 该次运行为 **FAIL**。
- 4/5/7 视为流程红线（docx skill 的核心承诺），FAIL 记缺陷并计入 benchmark。
- 其余项 FAIL → 记缺陷，不必判整次失败。
