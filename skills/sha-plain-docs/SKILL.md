# sha-plain-docs —— 受控技术文档写作

## 工作流（按序执行）

**1. 判类型选强度**（先做这一步，不要跳过）

- **完整应用**：操作手册、安全警告、故障排查 → 句长、主语、主动语态、步骤模板全部适用
- **选择性应用**：API 概念说明、更新日志 → 术语一致 + 指代明确优先，不机械套用步骤模板
- **不适用**：品牌文案、叙事文章 → 说明本 skill 不介入，按用户要求写
- 类型介于两者之间、拿不准 → **问用户要严格程度**，不要静默套默认值

**2. 定目标语言**：中文文档 → 动手前**必读 `references/rules-zh.md`**（这套中文规则不在你的默认能力里，靠记忆必漂移）；英文文档 → 读 `references/rules-en.md`。

**3. 搭结构**：先写结论或要点（每段首句是主题句），再按归类分组展开（组内互斥、组间穷尽、以上统下），步骤按实际执行顺序排列。套用下面 4 条结构护栏。

**4. 写内容**：套内核表与置信阶梯。改写场景先取原稿，逐句对齐事实，不添加原稿没有的数字、日期、条件或结论。

**5. 跑脚本**（不要靠肉眼替代）：

```bash
python3 scripts/check_plain.py <文档> [--lang zh|en] [--json]
```

按输出改到没有 `violation`。**改写场景**（有原稿或对话来源）：脚本报出的"强断言无来源标记"是硬违规，必须补来源、降级语态或删除；同时用 `--source <原稿>` 跑删改对比，检查 `仅/不得/除非` 一类警告词没被删掉。**规范型情态（必须/不得/禁止）是要求不是事实断言**：脚本列为 `normative_modality` 告警，无需来源标记；但改写场景不得新增原稿没有的要求。**绿场写作**（无原稿、靠模型知识写）：加 `--greenfield` 把该检查降级为告警，告警逐条自己复核，别当通过。

**6. 交付**：直接给文档，不写"我已按规则检查"这类过程性说明。

## 结构护栏（4 条，都是高频失败点）

- **序言=提示已知**：序言只写读者已知的背景与冲突（S+C），不引入新信息，序言 ≠ 摘要
- **标题=判断句非标签**：**所有标题（含小节标题）**都要带判断——写“重试在 3 次失败后停止”；不要写“重试机制”，也不要写“变更内容”“使用限制”“背景”“概述”这类名词标签。**标题已经给出判断，正文就不要再复述标题**：标题下面要写依据、条件、操作或后果，否则直接删掉这个标题、把判断并入上一段
- **归纳优先不混用**：同一组内用归纳（"建议 X，因为 1/2/3"），不在一组里混用演绎
- **空壳句禁用**：不写"存在以下 N 个问题：""本次更新的变更与使用限制如下"这类**空壳引导句**就列条目；每条都要带自己的判断，**标题已给判断时直接列依据/条件/操作/后果，不要用条目复述标题**

## 内核表（[通用] / [zh] / [en]）

- 结论先行[通用]：结论或要点先行，≤3 支撑，细节与例外后置
- 保留事实[通用]：走置信阶梯；不新增原文没有的数字、日期、条件、结论
- 一词一义[通用]：关键对象、状态、动作用首选术语，不轮换同义词；不直译 Success/Invalid 类状态词
- 显式主语+主动[通用]：一句一义，执行者明确；**系统自动行为与人工操作使用不同主语**
- 避免模糊副词[通用]：删"非常/特别/基本上"，或给出可量化依据
- 明确指代[通用]：不用"该/其/此/上述/相关"，重复具体对象名称
- 引号[通用]：简体中文用弯引号“ ”/‘ ’，不用直角引号「」『』（日文/繁中风格）；ASCII 直引号在英文原文/代码片段中保持原样
- 句长[zh]：无逗号单句 ≤40 字（30–39 字需语义明确），逗号分隔构件 ≤20 字
- 短句+主动[en]：一句一义，≤25 词，主动语态

## 置信阶梯（与 sha-plain-talk 共用）

- **有依据**（对话/文档内可核对来源 **或** 模型稳定知识）→ 可用强语态（一定/确认）。对话与文档来源写进句中；模型稳定知识（如"Docker 默认使用 overlay2"）不强制加来源标记
- **无依据·可定性为推测** → 弱语态（可能/据判断）+ 明示推断性质
- **无依据·不可判断** → 删除，不得伪装成事实
- **保护性类别**：警告、限制、例外无论有无依据都必须保留（可弱化语态，不得删除）
- **规范要求（必须/不得/禁止）**：是命令不是事实断言，不需要来源标记；但不得新增原稿没有的要求
- 来源标记只标新增信息：（你上一条消息）（来自 logcat）（监控报告显示）

## 操作与排查模板

**操作步骤**：前置条件 → 风险或限制 → 编号步骤（一步一动作，写清动作对象，不只写"处理"）→ 每步的预期结果 → 失败时的停止条件与恢复方式。

**故障排查**：可观察到的现象 → 需要收集的日志/状态/错误码 → 按证据价值与风险排序的检查（先低风险、可逆）→ 每项检查的判断条件 → 只有证据支持时才给原因 → 恢复操作、验证方式与停止条件。

## 参考文件

- `references/rules-zh.md`：中文受控写作全表（**规则权威源**；`docs/rules.md` 为展示副本）。**写中文文档前必读**。
- `references/rules-en.md`：英文精简 STE 方向性规则（长英文文档或要求更严时读）。
- `references/avoid-words.md`：黑话、机械直译、冗余套话、指代词全集；`check_plain.py` 读取此表。
- `scripts/check_plain.py`：确定性 lint。退出码 0=无违规，1=有违规，2=用法错误。
